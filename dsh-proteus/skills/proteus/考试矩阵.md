# 考试矩阵：五维指标、优先级与选题

考试矩阵回答一个问题：**下一道题该练哪一格？** 它不是成绩单，是选题器。

存储：`<root>/matrix.json`，schema `proteus.matrix/v1`。写入时机：`proteus_finalize` 成功后由 `upsertOutcome` 更新，不由模型手写。

---

## 1. cell key 格式

```
<exam>|<domain>|<knowledge_point>|<problem_type>|<difficulty>
```

例：`gaokao-math|calculus|GK.FUNC.DERIV|computation|medium`

规则：
- 由 `matrixCellKey(contract)` 计算，**不要手拼**。
- 五段都必须来自契约的枚举值：`exam ∈ {gaokao-math, kaoyan-math1, custom}`；`domain` 见 §2.1；`problem_type` 见 §2.1；`difficulty ∈ {easy, medium, hard}`。
- 一条契约只落一格。多知识点的题取 `knowledge_points[0]`（主干节点，写契约时就要把最核心的放第一位）。
- 同一题换了 `difficulty` 就是不同格，不要为了「合并统计」压低难度。

## 2. 五维指标定义（`cellStats`）

| 指标 | 公式 | 读法 |
|---|---|---|
| `coverage` 覆盖率 | `min(1, attempts / targetAttempts)`（`targetAttempts` 默认 5） | 这格练过几次。低于 1 说明**样本还不够**，此时正确率不可信 |
| `correctness` 正确率 | `verified / attempts` | 严格按 `Verified` 计数；`LowConfidence` 不算对 |
| `step_score` 步骤分率 | `points_earned / points_possible` | 应试能力的主指标。与正确率的差 = 「会做但拿不到分」的量 |
| `unknown_rate` 未知率 | `(unknown + low_confidence) / attempts` | 诚实度与能力边界的混合指标；异常高说明该格需要补基础或补工具 |
| `time_p50` 时间中位数 | `median(time_samples_s)` | 单位秒；样本少于 2 个时不可靠 |

原始计数字段（来自 `upsertOutcome`）：`attempts`、`verified`、`low_confidence`、`unknown`、`ambiguous`、`out_of_syllabus`、`points_earned`、`points_possible`、`time_samples_s`、`last_attempt_at`。

注意 `ambiguous` 与 `out_of_syllabus` 也会计入 `attempts`，但**不进**正确率分子——它们是题的问题，不是你的问题。若某格 `ambiguous/attempts > 0.3`，说明题面录入质量差，应修题而不是刷题。

**v0.1 读法（重要）**：v0.1 的证据介质只有 `numeric` 一种，任何解答的上限都是 `LowConfidence`，因此 `verified` **结构性地恒为 0**、`correctness` 恒为 0、`unknown_rate` 会吸收全部样本。此时：

- 不要把 `correctness = 0` 读成「全错」，那是能力边界；
- 主要信号改用 `step_score`（步骤分率）与 `time_p50`（速度）；
- `priority` 的前两项退化后，排序实际由 `(1-step_score)` 与时间项决定；
- 等 symbolic/formal 适配器接入、`verified` 开始非零后，本节读法失效，回到上面的原始口径。

## 3. 优先级公式

```
priority = 0.3*(1 - coverage)
         + 0.3*(1 - correctness)
         + 0.2*(1 - step_score)
         + 0.1*unknown_rate
         + 0.1*min(1, time_p50 / 900)
```

取值范围 `[0, 1]`，越大越该练。设计意图：
- 前两项各占 0.3：**没练过**和**练了不对**是最强的信号。
- `step_score` 占 0.2：会做但丢步骤分，权重低于「不会」。
- `unknown_rate` 占 0.1：诚实拒绝要计入，但不能主导选题。
- 时间项占 0.1，且以 `900s` 归一：慢题要练，但不该压过正确率。

**边界行为**：`attempts = 0` 时 `correctness = 0`、`coverage = 0`、`step_score = 0`（分母为 0 按 0 处理），此时 `priority` 主要由前三项拉到接近 0.8 —— 新格天然排前，这是对的。

## 4. 怎么读 `proteus_route` 输出

### `action: "lookup"`（需要 ledger）

```jsonc
{ "ok": true,
  "cell_key": "gaokao-math|calculus|GK.FUNC.DERIV|computation|medium",
  "cell": { "attempts": 3, "verified": 2, "points_earned": 26.5, "points_possible": 36, "time_samples_s": [420, 510] },
  "metrics": { "coverage": 0.6, "correctness": 0.67, "step_score": 0.74, "unknown_rate": 0.33, "time_p50": 465 },
  "priority": 0.42,
  "strategy": { "id": "symbolic_first", "name": "符号优先",
                "checklist": ["写出定义域", "符号求导", "判号/分类", "回代验证"],
                "preferred_checks": ["answer_format", "numeric_residual"] },
  "weak_siblings": [ { "cell_key": "…|GK.FUNC.EXTREMUM|…", "priority": 0.61 } ] }
```

按顺序读：

1. **`strategy.id` 决定解法路线**，不是建议。
   - `symbolic_first` → calculus / series / inequality：先符号推导，再数值回代。
   - `numeric_first` → probability / geometry：先数值/几何直觉定位，再补严格推导。
   - `formal_first` → proof：先写条件与结论，再补推导链。
   - `case_enumeration` → classification / 含绝对值 / 含参：先分类，`cases:N` 与 `param-range` 先行。
   - `construction_search` → construction：先构造候选，再用约束筛。
2. **`strategy.checklist` 就是本格的「必写步骤清单」**，逐条对应 `step_points`；漏一条大概率丢一个 step 的分。
3. **`preferred_checks` 是 S4 优先跑的检查**，不是全部；先用这些，再看 `available`。
4. **`priority` 只用于排序选题**，不要写进解答。
5. **`weak_siblings` 是同一 exam/domain 下优先级更高的兄弟格**，用于横向补短板；不要把它们混进当前题的契约。

### `action: "stats"`

返回 `{ totals, cells, weakest }`，`weakest` 按 `priority` 降序、`limit` 默认 10。这是「复习名单」，不是「成绩排名」。

## 5. 用弱格指导复习/选题

**选题规则（按顺序筛，命中即停）**：

| 条件 | 动作 |
|---|---|
| `attempts = 0` 且 `exam` 对得上 | 直接做：这是覆盖空洞，`priority` 天然最高 |
| `coverage ≥ 1` 且 `correctness < 0.5` | 回炉基础：先把该格对应大纲节点的定义/定理过一遍，再做题 |
| `coverage ≥ 1` 且 `step_score - correctness > 0.2` | 练**步骤书写**：技术上会，丢的是步骤分。照 `评分标准/*` 的踩分点重写解答 |
| `unknown_rate > 0.4` | 查工具链：多半是 `verification` 字段缺失（`reference_expr`/`equations`），不是能力问题 |
| `time_p50 > 900` | 练限时：拆成小问限时做，先拿步骤分再求完整 |
| 以上都不满足 | 按 `priority` 取最高的 `3` 格轮换 |

**一次只推 1 格**。矩阵的价值在于「可度量的短板」，同时推 5 格等于没有优先级。

**批量进攻的收敛判据**：某格 `coverage = 1` 且 `correctness ≥ 0.8` 且 `step_score ≥ 0.9`，视为该格收敛，停止投放，转向下一格。

## 6. 更新规则

- 只由 `proteus_finalize` 触发 `upsertOutcome`；手工编辑 `matrix.json` 会破坏 `updated_at` 与统计一致性。
- `points_earned` 取 `GradePrediction.predicted_points`，`points_possible` 取 `max_points`。
- `time_samples_s` 追加本次 `elapsed_s`，**保留最近 30 个样本**（`lib/matrix.js` 的 `TIME_SAMPLE_CAP = 30`；够算中位数，不无限膨胀）。
- `verified` 只在最终 `state = Verified` 时 +1；`LowConfidence` 进 `low_confidence`。
- 写入必须原子（`writeJsonAtomic`：先写 `.tmp` 再 `rename`）。读到损坏文件返回 **`MATRIX_CORRUPT`**（矩阵专用错误码，不是 `LEDGER_CORRUPT`），**不静默重置**。

## 7. 常见误读

| 误读 | 正确理解 |
|---|---|
| 「`correctness` 高就是学得好」 | 还要看 `step_score`。`correctness` 高而 `step_score` 低 = 应试失分严重 |
| 「`priority` 高 = 这题重要」 | `priority` 高 = **数据上短板**。大纲权重不参与公式 |
| 「`unknown_rate` 高是坏事」 | `Unknown` 是诚实输出（§2.9）。真正坏的是把 `unknown` 当 `pass` |
| 「修 `difficulty` 让统计更集中」 | 改 `difficulty` 会把数据切到别的格，等于污染两份统计 |
| 「`weak_siblings` 越多越好」 | 它只是排序结果；它衡量的是「没到位」，不是你做错了什么 |
