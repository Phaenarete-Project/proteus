# 审计包：结构、验证与重放

审计包的目的只有一个：**任何人拿到它，不依赖当时的对话上下文，也能复现答案与分数**。

存储：`<root>/audit/<contract_hex>.json`，schema `proteus.audit/v1`。`proteus_finalize` 会写一份；`proteus_audit write` 可覆盖等价内容；`verify` / `replay` 只读。

---

## 1. 字段

| 字段 | 内容 | 校验要点 |
|---|---|---|
| `schema` | 固定 `"proteus.audit/v1"` | 不符直接判包无效 |
| `bundle_id` | `"sha256:<hex>"` | 见 §2 |
| `contract` | 规范化后的完整 `ExamContract`（含 `contract_id` **和派生字段 `matrix_cell`**） | 必须能独立通过 `validateContract`，且 `matrix_cell === matrixCellKey(contract)` |
| `solution` | 最终提交的 `Solution`（`answer` + `steps`） | 必须与 `grade`、`evidence` 的 `claim` 对得上 |
| `evidence` | **当前 attempt** 的 `Evidence[]`（含 `status="unknown"` 与 `fail`）；旧 attempt 留在 ledger，不入包 | 每条都要有 `input_digest`/`output_digest`，且 `kind` 必须等于该 check 的固定种类 |
| `grade` | 重算后的 `GradePrediction`（`step_scores[].kinds` 由 grade 产出） | 必须能由 `contract + solution + replayed evidence` 复算出来 |
| `grade_drift` | 布尔：finalize 重算与账本既有 grade 是否不一致 | 为 true 时 state 不得是 `Verified`（会被降级并带 `GRADE_DRIFT`） |
| `state` | `{state, reason_codes, decided_at}` | `state` 必须是五态之一 |
| `budget` | `Budget` + 最终 `check` 结果；**顶层有 `phase`**，`budget.check.phase` 应与之相同 | 相位要与 `state` 的降级一致（`exhausted` 不得配 `Verified`） |
| `environment` | `plugin_version`、`node`、`platform`、`model`、`seed`、`rule_version`、`evidence_min_kinds` | 七项齐全，缺一项就不可重放 |
| `timeline` | 事件链 | 见 §3 |
| `verification` | `{attempt, plan, seed}`：本次实际执行的 attempt 号、检查 id 列表与随机种子 | `replay` **只按 plan/seed** 重跑；缺它则退化为「可审计不可复现」 |

**证据不许裁剪**：`fail` 和 `unknown` 是审计的关键信息。把失败证据删掉再打包，等同于伪造——`replay` 会立刻发现 `diffs`。

## 2. `bundle_id`

```
bundle_id = "sha256:" + sha256Hex(canonicalJson(bundle 去掉 bundle_id 字段))
```

`canonicalJson`：键排序、无空格、数字规范化。因此：
- JSON 字段顺序、缩进、换行不影响 `bundle_id`。
- **任何**字段值改动（包括 `detail` 里多一个空格、`timeline` 多一条）都会改变 `bundle_id`。
- 所以 `bundle_id` 是整包的完整性指纹，不是版本号。

## 3. timeline 链

每条元素：

```jsonc
{ "seq": 1, "at": "2026-10-29T15:40:54.000Z",
  "event": "contract.created", "prev": null, "hash": "sha256:…" }
```

约定（与 `verifyBundle` 的「逐条重算 timeline 链」对应）：

```
hash_n = "sha256:" + sha256Hex(canonicalJson({ seq, at, event, prev: hash_{n-1} }))
prev_1 = null
```

- `seq` 从 `1` 开始严格递增，不允许跳号或重号。
- `prev` 必须**逐字**等于上一条 `hash`（字符串比较）。
- 事件名就是实现的实际名，**只有下面 8 个**：

| 事件 | 何时写 |
|---|---|
| `contract.created` | `proteus_contract create` 落盘成功 |
| `budget.started` | `proteus_budget start`（每个契约**只有一次**） |
| `budget.checkpoint` | 每次 `proteus_budget check` |
| `evidence.appended` | 每次 `proteus_verify run` 追加证据 |
| `grade.predicted` | 每次 `proteus_grade` |
| `finalize.grade_recomputed` | finalize 内重算分数 |
| `finalize.decided` | finalize 内判定五态 |
| `finalize.completed` | finalize 收尾（**必须是最后一条**） |

- **不存在** `verify.run`、`grade.computed`、`finalize.done`、`audit.written`。旧文档里的这四个名字已作废，看到它们说明文档/实现版本错配。
- 最小集合：`contract.created` 与 `finalize.completed` 不可省略。包里缺 `finalize.completed` ⇒ 这是 finalize 之前的旧快照，判**不可重放**并提示重新 finalize。
- 任何一条被改动，`hash` 变 → 下一条 `prev` 对不上 → 链断。这是「不可抵赖」的来源。

> 封闭字段集合属于 `lib/audit.js` 的实现细节。技能层的义务是：**只读、不改写 timeline**；发现 `verify` 报链断，一律按「不可重放」处理并上报，不要手工修 hash 去「修好它」。

## 4. `verify` 语义

`proteus_audit verify` 是语义级校验，**必查下面 6 项**（任何一项不过即 `ok:false`）：

| # | 必查项 | 判据 |
|---|---|---|
| 1 | **证据 kind / digest / id 重算** | 对每条 `evidence`：`kind` 必须等于该 `check` 的固定种类（`numeric_residual`/`expression_sample`/`domain_probe` → `numeric`，`answer_format` → `structural`）；`input_digest`/`output_digest`/`evidence_id` 逐条重算后必须一致。**改 `kind` 骗独立种类、改 `status` 骗 pass，都会在这里被抓** |
| 2 | **重跑 checks** | 按 `bundle.verification.plan` 与 `verification.seed` 重跑 `runChecks`，逐条比对 `check`/`claim`/`status`/`detail`/`evidence_id`（与 `replay` 共用同一实现；`verify` 只报差异，不改包） |
| 3 | **重算 grade** | 用 `contract + solution + evidence` 与 `proteus-rubric/v1` 重算，逐字段比对 `predicted_points`、`step_scores`、`deductions`、`coverage`、`confidence` |
| 4 | **重算 state** | 按 §2.9 顺序重判五态（含证明题 `formal` 门），与 `bundle.state.state` 比对；`reason_codes` 也要对得上 |
| 5 | **dangling refs** | `solution.steps[].evidence_refs` 的每个 id 都必须在 `bundle.evidence` 里存在；悬空引用 = 伪造，直接判失败 |
| 6 | **`exhausted` 不得 Verified** | `budget.phase`（顶层）或 `budget.check.phase` 为 `exhausted` 时，`state` 不得是 `Verified`（§2.9-5）；证明题还要求 `independent_kinds` 含 `formal`/`human` |
| 附加 | **契约与派生字段** | `contract` 能独立通过 `validateContract`（`state` 不应为 `invalid`）；`contract.matrix_cell === matrixCellKey(contract)`；`bundle_id` 与 timeline 链自洽 |

返回 `{ok, bundle_id, issues}`。`issues` 每一项都要带 `check` 名 + 「期望 / 实际」，能直接定位到上面 6 项中的哪一项。

**`verify` 通过 ≠ 答案正确**。它证明「包没被篡改、内部自洽、结论可复算」；但 `numeric` 抽检只能采样，答案的数学对错最终仍由证据强度与人类复核决定。

## 5. `replay` 语义

`proteus_audit replay` 才是重跑：

1. 从包里取出 `contract` 与 `solution`。
2. 按 **`bundle.verification.plan`**（本次实际执行的检查 id 列表）与 **`bundle.verification.seed`** 重跑 `runChecks`——**不是**按 `contract.verification.checks` 的全量重跑。verify 时只跑过 `['answer_format']` 的子集，replay 就只该跑这一项；按全量重跑会得到一堆 `EXTRA_IN_REPLAY` 假阳性。
3. 与包里的 `evidence` 逐条比对（同 `check`、同 `claim`、同 `status`、同 `kind`），输出 `diffs`。
4. 返回 `{ok, checks, diffs}`。

约束：
- `replay` **不重新推理**，只重跑确定性检查。它无法证明「模型当时没瞎编」，只能证明「当时跑的那些检查现在跑还是这个结果」。
- 检查不可用时，包里的证据是 `status="unknown"`；replay 仍按 plan 重跑，比对的是 `unknown` 这种状态本身，**不把 `unknown` 算失败**，但要在报告里写明哪些检查当时不可用。
- `verification` 缺失（旧包）时：改用 `contract.verification.checks` 与 `environment.seed` 兜底，并在报告里标「可审计不可复现（包无 plan/seed）」。
- `diffs` 非空 ⇒ `ok=false`。此时不允许把包当作「已验证」。

## 6. 怎么判断一份解答「可重放」

按三步走，**任何一步不过就不叫可重放**：

### 第一步：结构可校验

- [ ] `schema` 正确、`bundle_id` 可重算且一致。
- [ ] `contract` 能独立通过 `validateContract`（`state` 不应是 `invalid`）。
- [ ] `solution.steps[].id` 与契约 `step_points[].id` 一一对应。
- [ ] `state.state` 是五态之一，`reason_codes` 只用受控取值。

### 第二步：证据可重算

- [ ] 每条 `evidence` 的 `kind` / `check` / `claim` / `status` 齐全。
- [ ] `status="fail"` 与 `"unknown"` 的条目**仍在**（没有为了好看被删）。
- [ ] 证据里的 `claim` 都能在 `solution.steps` 或 `answer` 上找到落点。
- [ ] `unknown` 没有被当成 `pass`（`grade` 的 `step_scores` 不能给依赖 unknown 的步骤满分）。

### 第三步：结论可复现

- [ ] `replay` 的 `diffs` 为空。
- [ ] 重算的 `predicted_points` 与包里 `grade.predicted_points` 完全相等（含 0.5 取整）。
- [ ] `bundle.verification.plan` / `bundle.verification.seed` 都存在，且与证据集合自洽（plan 覆盖所有 `evidence[].check`）。
- [ ] `environment.seed` / `rule_version` / `plugin_version` 都在，且与实际运行环境一致。
- [ ] `state` 与 `budget.phase` 不矛盾：`phase="exhausted"` 而 `state="Verified"` ⇒ 违反 §2.9-5，判不可重放。

四条全过 → 这份解答可重放。只过前两步 → 可审计但不可复现（典型：`verification` 字段缺失，numeric 检查无法重跑）。

## 7. 常见「不可重放」原因

| 现象 | 根因 | 处置 |
|---|---|---|
| `bundle_id` 对不上 | 包被手工编辑过（哪怕是格式化） | 重新 `finalize`，不要修 JSON |
| timeline 链断 | 漏写一条事件，或改了 `at` | 重新生成；绝不手写 `hash` |
| `diffs` 非空 | 期间改过 `rule_version` / `seed`，或 replay 按全量 plan 重跑（应改按 `verification.plan`） | 用包里的 `verification` 与 `environment` 复现 |
| 包内缺 `finalize.completed` | finalize 先写包、后追加事件（旧版行为） | 重新 finalize 生成包；旧包只能当「未完成快照」 |
| 大量 `NO_REFERENCE_EXPR` | 契约没写 `verification.reference_expr` / `equations` | 补契约字段后重跑 S4–S6 |
| `state=Verified` 但 `independent_kinds` 只有 1 类 | `evidenceMinKinds` 被临时调低，或谎报了证据种类 | 恢复默认 2 并核对 evidence 的 `kind`；**v0.1 下任何 `Verified` 都应按异常处理** |
| `phase=exhausted` 但状态是 `Verified` | 违反 §2.9-5 | 降为 `LowConfidence`，加 `TIME_EXHAUSTED` |
| `grade` 与重算差 0.5 | `roundHalf` 口径不一致 | 确认双方都用 0.5 整数倍取整（§2.5-5） |

## 8. 与其他产物的关系

| 产物 | 角色 |
|---|---|
| `<root>/ledger/<hex>.json` | 工作账本，可随过程变化；审计包的**来源** |
| `<root>/solutions/<hex>.md` | 面向人的解答（见 `输出协议.md`）；审计包 `solution` 的渲染版 |
| `<root>/audit/<hex>.json` | **只读快照**，一旦生成即冻结 |
| `<root>/matrix.json` | 汇总统计，与审计包无强绑定 |

审计包冻结后，后续任何「改一下解答再交」都必须生成**新**审计包（新 `contract_id` 或新 `solution` ⇒ 新 `bundle_id`）。用旧包配新解答是审计欺诈。
