# 输出协议：面向评分者的解答

`proteus_finalize` 把解答写到 `<root>/solutions/<contract_hex>.md`，由 `renderSolutionMarkdown` 生成。本文件规定那份文件的**实际结构**——与 renderer 逐块对齐，**不是**旧版 A–F 六区块（旧版已废弃，见 §7）。

## 0. 一条铁律

> 评分者只看得到这份 Markdown。工具里有什么证据，没写进这份文件就等于不存在；反过来，写进去的每一句都要能追到证据或明确标成推断。

所以：**没有 `evidence_refs` 的步骤，其步骤标题的类型位必须是 `〔heuristic〕`**，不许用肯定语气混过去。

---

## 1. 文件骨架（九个区块，顺序固定）

| # | 区块标题（逐字） | 内容 |
|---|---|---|
| 1 | `## 契约摘要` | 考试 / 知识点 / 题型 / 答案形式 / rubric 来源与总分 / 时间预算 |
| 2 | `## 题目` | 题面原文 |
| 3 | `## 答案` | `answer.value`（代码体）+ 单位 |
| 4 | `## 步骤` | 每个 step 一个 `###` 小节（格式见 §1.1） |
| 5 | `## 评分预测（规则分为准，不是权威）` | 预测得分 / 答案分 / 置信度 / 独立证据种类 + 逐项表 + 扣分项 |
| 6 | `## 验证状态` | `**<五态>**（reason_codes）` |
| 7 | `## 陷阱检查` | 逐条 `- Txx [severity/basis] detail（-扣分）`，无则写「（未发现规则级陷阱）」 |
| 8 | `## 证据` | 逐条 `- [status] check / kind：detail`，无则写「（无证据）」 |
| 9 | `## 审计` | 审计包路径 + verify/replay 提示 |

**九个区块一个都不能少**；renderer 缺哪块就是程序缺陷，不是「可以省」。区块之间用空行分隔，标题逐字一致（`## 评分预测（规则分为准，不是权威）` 括号里的说明也是标题的一部分）。

### 1.1 步骤小节格式

```
### S1（2/2）〔structural,numeric〕
<该步正文，可直接抄进答题纸的书面语>

tags: domain, uses:G1
evidence_refs: ev_3f7a91c2d4e8, ev_c9e1a5b7d340
```

规则：

- 标题格式固定为 `### <step.id>（<earned>/<max>）〔<kinds，逗号分隔，无空格>〕`。
- `<kinds>` 取 `grade.step_scores[].kinds`（该步实际参与计分的证据种类）。
- **该步没有任何证据种类时写 `〔heuristic〕`**——这是「未验证」的显式标记，不是可选项。
- `tags:` 行只在 `solution.steps[].tags` 非空时出现，逗号分隔。**tag 必须取自受控词表**（`domain`/`cases:N`/`param-range`/`units`/`conclusion`/`theorem:<name>`/`check:extraneous`/`uses:<givenId>`/`rank`/`convergence`/`independent`/`forward`/`backward`/`iff`/`square-both-sides`/`subset`/`complement`），且**与正文一致**——漏贴会触发对应陷阱扣分，错贴能暂时免检但审计会核对。
- `evidence_refs:` 行只在非空时出现，**只填 `proteus_verify run` 返回的 `ev_<12hex>` id**，不填自造 id、不填别的字段名。
- 没有 `tags`/`evidence_refs` 时整行省略（renderer 行为），不要写 `tags: (无)`。

### 1.2 五个区块的硬约束

- **`## 答案`**：`answer.value` 必须非空（空则状态直接落 `Unknown`）；有单位时紧跟数值，不加括号。
- **`## 评分预测`**：四个要点行 + 步骤表 + 扣分项，数字**只能来自 `proteus_grade`**；手算对照不许写进这个区块。
- **`## 验证状态`**：五态之一，冒号后不得加形容词（不许「基本已验证」）。
- **`## 陷阱检查`**：只列 `proteus_grade` 返回的 `traps[]`；没命中也必须出现该区块与「（未发现规则级陷阱）」。
- **`## 审计`**：路径写 `audit_path` 原值；`(未生成)` 只允许出现在非 finalize 场景。

## 2. 「部分得分步骤」怎么写

适用：`Unknown` / `LowConfidence` / 时间相位 `salvage`。原则是**按 rubric 的 step 逐条对齐**，让评分者一眼看到能给的每一分。

1. **先写「已确认的事实」**：题设条件、定义域、已知公式——通常是 `structural` 分。
2. **再写「已算出的中间量」**：哪怕不足以得答案，只要是被验证过的中间结果就写出来，并挂 `evidence_refs`。
3. **卡点写在正文里**，一句话说清缺什么（缺条件、计算量过大、时间耗尽）；不要塞进 `## 验证状态`。
4. **不写半截推导**：推到一半的式子对评分者无意义。要么给一个完整可用的中间结论，要么不写这一步。
5. **按 rubric 打字**：rubric 要 `S3` 写「解 `f'(x)=0` 并判号」，就单独写这一步并挂证据，即使后面没做完。
6. **没证据就标 `〔heuristic〕`**：宁可标题上写着未验证，也不要让评分者误以为这步被机器验过。

反例（不要这样）：

> 「由题意可得 …（一堆变形）… 所以答案应该是 … 吧。」

正例（可以这样）：

```
### S1（2/2）〔structural〕
函数定义域为 (0,+∞)。

evidence_refs: ev_91c4a7f2d03e

### S2（3/3）〔numeric〕
由 f(x)≤0 得 a ≥ ln x / x 对一切 x>0 成立。

evidence_refs: ev_2b8e40d1a6f9

### S3（0/3）〔heuristic〕
卡点：需比较 g(x)=ln x/x 的极值，但未完成求导后的判号，故未给出最大值。
```

## 3. 示例一：满分形态（v0.1 实际为 LowConfidence）

**先读这段再看例子**：本示例演示 `Verified` 的输出格式与达标条件。v0.1 的三个检查（`numeric_residual`/`expression_sample`/`domain_probe`）全部产 `numeric`，`independent_kinds` 最多 1 类，所以**同一份满分解答在 v0.1 一定落在 `LowConfidence`**。`## 验证状态` 里同时给出目标态，实际以第一行为准。

**题面**：设 `f(x)=x^3-3x`，求 `f` 的单调区间与极值。（12 分）

```markdown
# Proteus 解答：2024 示例卷 21

## 契约摘要

- 考试：gaokao-math
- 知识点：GK.FUNC.MONO, GK.FUNC.EXTREMUM
- 题型：computation
- 答案形式：interval
- rubric 来源：inferred，总分 12
- 时间预算：900s

## 题目

设 f(x)=x^3-3x，求 f 的单调区间与极值。

## 答案

`增区间(-∞,-1)和(1,+∞)；减区间(-1,1)；极大值2，极小值-2`

## 步骤

### S1（2/2）〔structural〕
函数 f(x)=x^3-3x 的定义域为 R。

tags: domain

### S2（3/3）〔numeric〕
f'(x)=3x^2-3=3(x-1)(x+1)。

tags: uses:G1
evidence_refs: ev_a17c5e93b204, ev_c9e1a5b7d340

### S3（3/3）〔numeric〕
令 f'(x)=0 得 x=-1 或 x=1。
当 x<-1 时 f'(x)>0；当 -1<x<1 时 f'(x)<0；当 x>1 时 f'(x)>0。

tags: cases:3
evidence_refs: ev_88c1d9e07b3a

### S4（2/2）〔structural〕
f(x) 在 (-∞,-1] 与 [1,+∞) 上单调递增，在 [-1,1] 上单调递减；
极大值 f(-1)=2，极小值 f(1)=-2。

## 评分预测（规则分为准，不是权威）

- 预测得分：12 / 12
- 答案分：2 / 2
- 置信度：0.93
- 独立证据种类：numeric

| 步骤 | 得分 / 满分 | 理由 |
|---|---|---|
| S1 | 2 / 2 | structural pass |
| S2 | 3 / 3 | numeric pass（expression_sample + numeric_residual） |
| S3 | 3 / 3 | numeric pass |
| S4 | 2 / 2 | structural pass |

## 验证状态

**LowConfidence**（EVIDENCE_INSUFFICIENT）

> 目标态（symbolic/formal 适配器接入后）：**Verified**，置信度 0.97。

## 陷阱检查

（未发现规则级陷阱）

## 证据

- [pass] expression_sample / numeric：在 8 个采样点上 f'(x) 与 3x^2-3 一致
- [pass] numeric_residual / numeric：residual=0 at x=2（f'(2)=9）
- [pass] domain_probe / numeric：x=-2,0,2 处符号依次 +,-,+
- [pass] answer_format / structural：interval 格式合法；S4 正文非空

## 审计

- 审计包：`proteus/audit/1b7e9d3c4a82.json`
- 用 `proteus_audit action=verify` 校验哈希链，用 `action=replay` 重跑确定性检查。
```

**风险提示**：全部分数由 `numeric` 撑起，没有任何符号引擎参与；不要把这份解答说成「符号验证通过」。区间端点开闭若阅卷口径为全开，`S4` 应改写成「在 `(-∞,-1)`、`(1,+∞)` 上递增」。

## 4. 示例二：LowConfidence（v0.1 的常态与上限）

**题面**：已知 `f(x)=ln x - ax`，若 `f(x) ≤ 0` 对一切 `x>0` 恒成立，求 `a` 的取值范围。（12 分）

```markdown
# Proteus 解答：示例卷 导数恒成立

## 契约摘要

- 考试：gaokao-math
- 知识点：GK.FUNC.EXTREMUM, GK.INEQ.BASIC
- 题型：computation
- 答案形式：interval
- rubric 来源：inferred，总分 12
- 时间预算：900s

## 题目

已知 f(x)=ln x - ax，若 f(x) ≤ 0 对一切 x>0 恒成立，求 a 的取值范围。

## 答案

`a ≥ 1/e`

## 步骤

### S1（2/2）〔structural〕
由真数大于 0，定义域为 (0,+∞)。

tags: domain
evidence_refs: ev_0c3b7f5a92d1

### S2（3/3）〔numeric〕
f(x)≤0 即 ln x ≤ ax。因 x>0，两边同除以 x 得 a ≥ ln x / x 对一切 x>0 成立。

tags: uses:G1
evidence_refs: ev_6a19d3c85f27

### S3（3/3）〔numeric〕
设 g(x)=ln x / x（x>0）。g'(x)=(1-ln x)/x^2，
故 g 在 (0,e) 上递增、在 (e,+∞) 上递减，最大值 g(e)=1/e。

evidence_refs: ev_b41f8e2a6c05

### S4（2/2）〔structural〕
由 a ≥ g(x) 恒成立等价于 a ≥ g(x) 的最大值，得 a ≥ 1/e。

## 评分预测（规则分为准，不是权威）

- 预测得分：10 / 12
- 答案分：2 / 2
- 置信度：0.78
- 独立证据种类：numeric

| 步骤 | 得分 / 满分 | 理由 |
|---|---|---|
| S1 | 2 / 2 | structural pass |
| S2 | 3 / 3 | numeric pass |
| S3 | 3 / 3 | numeric pass |
| S4 | 2 / 2 | structural pass |

扣分项：
- T08 -2：givens 含单字符参数 `a`，steps 无 param-range tag

## 验证状态

**LowConfidence**（EVIDENCE_INSUFFICIENT, TRAP_UNRESOLVED）

## 陷阱检查

- T08 [major/rule] givens 含单字符参数 a，未打 param-range tag（-2）

## 证据

- [pass] answer_format / structural：S1 正文非空
- [pass] expression_sample / numeric：恒等变形在 8 个采样点一致
- [pass] expression_sample / numeric：g'(x) 与 (1-ln x)/x^2 一致

## 审计

- 审计包：`proteus/audit/7d40c1b9e635.json`
- 用 `proteus_audit action=verify` 校验哈希链，用 `action=replay` 重跑确定性检查。
```

**未验证项与风险**

- **`LowConfidence` 在这里是必然，不是这份解答不够好**：v0.1 只有 `numeric` 一种独立介质，`independent_kinds` 上限为 1，而 `Verified` 要 ≥2 类。即使把每个检查都跑满，状态也不会变。这是能力边界，不要靠改证据种类绕过。
- T08 的 −2 **不是数学错误**，是「没给参数分类留痕」：补一步打 `param-range` tag，写出「当 `a<1/e` 时存在 `x` 使 `f(x)>0`；当 `a≥1/e` 时恒有 `f(x)≤0`」，该扣分即消失。
- 端点：`a=1/e` 时 `g` 取到最大值，故取闭端点；若阅卷要求写成 `a ∈ [1/e, +∞)`，与 `a ≥ 1/e` 等价。

## 5. 示例三：Unknown + 部分得分步骤（片段）

**场景**：题目要求证明「`f` 在 `[a,b]` 上一致连续」，只完成了条件梳理，未完成论证；时间相位 `salvage`。

```markdown
## 步骤

### S1（2/2）〔structural〕
f 在闭区间 [a,b] 上连续（题设 G1），故 f 在 [a,b] 上有界（G2 给出上界 M）。
注：不能用「f 连续故一致连续」——那正是待证结论。

tags: uses:G1, uses:G2

### S2（0/3）〔heuristic〕
卡点：需用「对任意 ε>0 取 δ=ε/(2M)」构造一致连续的 δ，但未完成放缩，故不写结论句。

### S3（0/4）〔heuristic〕
未完成，不编造。

### S4（0/3）〔heuristic〕
未给出结论句。按 T14 本应补「故 f 在 [a,b] 上一致连续，证毕」，
但前提是 S2 成立，故此处不补——补了就是伪造。

## 验证状态

**Unknown**（NO_ANSWER, EVIDENCE_INSUFFICIENT）
```

要点：S1 主动写出「这正是待证结论，不能作为依据」，比假装没看见更容易被接受；S4 不补结论句，因为补了也没有依据，属于伪造；`〔heuristic〕` 就是给评分者看的「此步未验证」标签。

## 7. 旧版 A–F 六区块已废弃

早期草案规定「契约摘要 / 分步解答 / 证据清单 / 评分预测 / 状态行 / 未验证项」六区块（A–F），带 `证据:` 行与 F 区。该版本与 renderer 不一致，已作废：

| 旧版 | 现在去哪了 |
|---|---|
| A 题目契约摘要 | `## 契约摘要` |
| B 分步解答 | 拆成 `## 题目` + `## 答案` + `## 步骤` |
| C 证据清单 | `## 证据`（格式改为 `- [status] check / kind：detail`） |
| D 评分预测 | `## 评分预测（规则分为准，不是权威）` |
| E 状态行 | `## 验证状态` |
| F 未验证项与风险 | 「卡点」写进步骤正文；「未验证」由步骤标题的 `〔heuristic〕` 表达；其余风险写进你的对话回复，不写进 Markdown |

仍要保留的原则：**不伪造证据、不手改分数、不用肯定语气掩盖未验证**。变的只是载体，不是纪律。
