## 2. R1–R5 逐条复核

### R1：伪造 `environment.evidence_min_kinds=1` + `state=Verified`

**已修复。**

```
R1 direct false CONFIG_MISMATCH,STATE_MISMATCH
R1 tool verify false CONFIG_MISMATCH,STATE_MISMATCH
R1 tool replay false CONFIG_MISMATCH,STATE_MISMATCH
```

原因：`verifyBundleSemantics(bundle, {evidenceMinKinds})` 现在把调用方配置（默认 2）与 `bundle.environment.evidence_min_kinds` 比对，不一致直接 `CONFIG_MISMATCH`；带伪造 state 的包同时触发 `STATE_MISMATCH`。`handleAudit verify/replay/write` 均传入 `ctx.cfg.evidenceMinKinds`（`lib/tools.js:844,868,881`）。

补测：测试 `test/security.test.js:385` 覆盖同一攻击；`node --test` 通过。

## 3. 非阻塞观察（不影响本次“可交付”结论）

1. **`evidenceMinKinds` 仍可由 profile 配置为 1/0**：此时 `verifyBundle` 按调用方配置也会接受 numeric-only 的 `Verified`。这是显式配置语义（非默认路径），但若仍要维持“v0.1 任何 Verified 都异常”的对外承诺，建议在 Config 层 clamp `>=2` 或写入文档。默认 2 下 R1 已封闭。
2. **finalize 文件写入顺序变为“矩阵先行”**：若矩阵成功但 solution/audit 写入失败，矩阵可能已多记一次 attempt 而 finalize 失败。本次 R3 只要求矩阵失败时不产文件，这一点已满足；该反向失败路径未在本次断言内，列为后续加固项（不影响证据/审计结论的可伪造性）。
3. **T18** 仍未与技能说明的 `problem_type ∈ {computation, classification}` 门槛对齐（上一轮 R6，未在本次 R1–R5 清单）。属于扣分误报风险，不是信任根问题；建议 v0.1.1 修。
4. 测试临时目录仍使用 `/tmp`；符合 Lead 本次“可用 /tmp、清理干净”的约定，不视为缺陷。
